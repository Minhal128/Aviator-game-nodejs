Product Overview

Chicken Road is a self-contained, browser-based casino-style game built entirely with native HTML5, CSS3, and modern JavaScript (ES6 modules). No external frameworks, no build tools, and no server-side language are required to run the game. Open the file in a browser and play.

The game concept is a lane-crossing risk game: the player character (a chicken) starts on a pavement and advances across traffic lanes one step at a time. Each successful crossing increases a multiplier. The player may cash out at any point to collect their winnings, or continue advancing for a higher reward at the risk of being hit by a vehicle. The outcome of each lane is determined by a seeded, deterministic pseudo-random number generator (PRNG), making results reproducible and auditable.

Target Users

  • Game developers or agencies building HTML5 casino or gambling-style mini-games.
  • iGaming platform operators looking for a ready-to-integrate game widget.
  • Web developers who need a fully functional game template to customise.

  • Starting point for a custom-branded road-crossing casino game.

Key Features

Gameplay & Logic

  • Lane-crossing risk mechanic — the player advances one lane at a time and may stop to cash out at any moment.
  • Dynamic multiplier system — each lane carries a mathematically calculated multiplier that grows as the player progresses deeper into traffic.
  • Four difficulty modes — Easy, Medium, Hard, and Hardcore. Each mode defines its own survival probability curve, RTP (return-to-player) ratio, volatility factor, and decay rate.
  • Instant cashout — the player can collect winnings at any lane with a single button press.
  • Wallet system — a virtual wallet tracks the current balance. Bets are deducted on game start; winnings are added on cashout. A refill button restores $100 when the balance is low.
  • Bet management controls — MIN / MAX stepper buttons, a numeric input field, and four quick-select shortcut buttons ($2, $3, $8, $20).
  • Insufficient funds protection — the Play button displays a temporary warning if the wallet balance is below the selected bet amount.

Pseudo-Random Number Generator (PRNG)

  • Seeded PRNG engine — uses the cyrb128 hashing algorithm combined with the sfc32 generator for high-quality randomness.
  • Three-part seed — outcomes are derived from a server seed, a client seed, and a per-round nonce. The seed string changes every round, making outcomes unique and non-repeating.
  • Deterministic results — given the same seed combination, the sequence of safe and crash lanes is always identical, enabling provably-fair verification.

Rendering & Animation

  • Canvas-based sprite animation — the player character is rendered on an HTML5 <canvas> element at 24 fps using sprite-sheet frame data defined in JavaScript.
  • Three character states — idle animation, jump animation, and crash image, each backed by a separate sprite sheet.
  • Hardware-accelerated transforms — all road and player movement uses translate3d and CSS transitions with a custom cubic-bezier easing, offloaded to the GPU via will-change: transform.
  • requestAnimationFrame game loop — smooth, frame-rate-aware rendering loop with timestamped delta control.
  • Nine randomised vehicle sprites — cars are drawn from a pool of nine PNG images, chosen at random per lane.
  • Dynamic vehicle aspect-ratio loading — each car image is introspected after loading so its rendered height matches its actual proportions.
  • Crash animation sequence — when a collision occurs, the crash car spawns at high speed and runs over the character with a tinted visual effect before the game resets.
  • Safety roadblock pop-in animation — on a safe lane, two barrier elements appear above and below the player with a scale-in CSS keyframe animation.

Audio

  • Looping background music with real-time volume control.
  • Independent SFX volume control (separate from music).
  • Sound events: button clicks, game start (GO), cashout, crash, car pass-by, car honk (two variants), and braking.
  • Polyphonic SFX playback via cloneNode() — overlapping sounds play simultaneously without interrupting each other.

User Interface

  • Full-screen sliding sidebar panel with backdrop blur for wallet and audio settings.
  • Hamburger toggle button overlaid on the game viewport.
  • Live multiplier badge that floats above the player character and updates on each lane advance.
  • Win toast notification that slides down from the top of the screen on a successful cashout, displaying the achieved multiplier.
  • Dashboard panel (pre-game controls) and active game panel (GO / Cashout buttons) are swapped in and out automatically.
  • Touch-friendly controls — large tap targets, no hover-only interactions.

Architecture

  • Modular ES6 code split across four files: app.js, math.js, audio.js, sprites.js.
  • An alternative single-file build (h.js) is included for environments that do not support ES6 modules.
  • Zero external libraries or CDN dependencies.

Installation Guide

Requirements

  • A modern web browser (Chrome 80+, Firefox 75+, Edge 80+, Safari 14+).
  • A local or remote web server capable of serving static files.
  • No Node.js, PHP, database, or build tool is required.
Important: The modular version (index.html + js/app.js) uses ES6 import statements. Browsers do not allow module imports when opening HTML files directly from the filesystem (file:// protocol). You must serve the files through a web server.

Option A — Local Development Server (Quickest Method)

  1. Install Node.js if not already installed.
  2. Open a terminal or command prompt in the project root folder.
  3. Run the following command: 
    npx serve .
  4. Open the URL shown in the terminal (typically http://localhost:3000) in your browser.

Alternatively, if you use Visual Studio Code, install the Live Server extension, right-click index.html, and select Open with Live Server.

Option B — Apache / Nginx / cPanel Web Hosting

  1. Extract the downloaded ZIP archive on your computer.
  2. Connect to your hosting account using FTP (FileZilla, WinSCP, etc.) or the hosting control panel file manager.
  3. Upload the entire extracted folder to the public_html directory (or a subdirectory of your choice).
  4. Visit the corresponding URL in your browser, for example: https://yourdomain.com/chicken-road/.

No .htaccess modifications or server configuration changes are required.

Option C — Single-File Version (No Module Support)

If your environment cannot serve ES6 modules, use the alternative single-file build:

  1. Open index.html in a text editor.
  2. Replace the last <script> tag: 
    <!-- Replace this: -->
<script type="module" src="js/app.js"></script>

<!-- With this: -->
<script src="js/h.js"></script>
  3. Save the file and open it in a browser. This version has no module imports and will work over file:// as well.

Code Architecture & Logic Overview

High-Level Flow

  1. On page load, initPRNG() is called with the server seed, client seed, and nonce 0. This seeds the random number generator for the pre-built road layout.
  2. buildInitialHighwayLayout() creates 25 lane <div> elements and calls generateLaneTraffic() on each. This populates each lane with a random number of cars, a direction (incoming or outgoing), a speed, and a manhole cover showing the lane multiplier.
  3. requestAnimationFrame(updateGameLoop) starts the render loop. Each frame: car positions are updated, sprite frames are drawn to the canvas, proximity sounds are evaluated, and live collisions are checked.
  4. When the player presses Play, the nonce increments, the PRNG is re-seeded, the bet is deducted, and the game enters an active session.
  5. Each press of GO moves the player one lane right, creates a new lane at the end of the road, checks the lane outcome (safe or crash), and either places safety barriers or schedules a crash car spawn.
  6. Old lanes beyond a threshold of six columns behind the player are removed from the DOM to keep memory usage stable (virtual infinite scrolling).
  7. On Cashout or after a crash animation completes, the game calls resetGameToDashboard(), which re-seeds the PRNG and calls resetGameEnvironment() to clear all state and rebuild the road for the next round.

Key Modules

math.js — PRNG & Multiplier Engine

  • cyrb128(str): A 128-bit non-cryptographic hash function that converts the combined seed string into four 32-bit integers used to seed the generator.
  • sfc32(a, b, c, d): A fast, high-quality pseudo-random float generator. Returns a closure that yields a new float in [0, 1) on each call.
  • initPRNG(serverSeed, clientSeed, gameNonce): Combines the three seed components, hashes them, and assigns the resulting generator to getRNG.
  • calculateMultiplierForIndex(targetIdx, difficultyLevel): Calculates the displayed multiplier for a given lane index. It compounds the survival probability for all preceding lanes, divides the mode RTP by that compound probability, and applies a volatility bonus that grows nonlinearly as the player reaches deeper lanes.

audio.js — Audio Engine

  • Each sound effect is an Audio DOM object declared at module level, so assets are pre-loaded when the script is parsed.
  • playSound(audioObj) calls cloneNode() on the audio object before playing. This creates a disposable copy, which allows the same sound to overlap with itself (polyphonic playback) without interrupting an in-progress sound.
  • Music volume and SFX volume are maintained as separate state values, allowing the user to mute effects without affecting music and vice versa.

sprites.js — Sprite Data

  • Idle and jump sprite sheets are 1280×1280 px grids (5 columns × 5 rows, 256×256 px per frame). Frame coordinates are stored as arrays of { x, y, w, h } objects.
  • Three Image objects (idle, jump, crash) are pre-loaded at module initialisation time.

app.js — Game Controller

  • generateLaneTraffic(laneEl, domIdx, absIdx): Populates a lane. Determines if the lane is safe or a crash lane using checkIsCrashLane(), picks a random car count, direction, and speed, and creates car elements positioned at evenly spaced starting offsets.
  • checkIsCrashLane(domIdx, absIdx): Calls getRNG() once and compares the result to the survival probability for that lane index and difficulty. The result is cached in safeLaneMap so subsequent calls for the same lane are consistent.
  • updateGameLoop(timestamp): The main requestAnimationFrame callback. Updates all car positions, draws the current sprite frame to canvas, triggers proximity audio (honking, braking), and checks live collisions.
  • spawnInstantCrashCar(laneEl, domIdx): Removes existing cars from the crash lane and spawns a single high-speed, darkened vehicle heading directly at the player.
  • triggerCarOverDeath(hittingCar): Marks the game as over, plays the crash sound, reparents the player element inside the colliding lane for correct Z-ordering, switches the sprite to the crash image, and schedules a timed reset.
  • resetGameEnvironment(): Clears all DOM lane elements, resets all state variables, and calls buildInitialHighwayLayout() to rebuild the road.

Lane Indexing

Two lane index values are tracked simultaneously. currentLaneIndex is the DOM position of the player's current lane within the roadContainer children array. absoluteLaneIndex is the cumulative count of lanes crossed across the entire session, including lanes removed from the DOM. The multiplier and survival calculations use the absolute index. The DOM index is used for rendering and collision checks.

Performance & Optimization Notes

  • GPU-accelerated rendering — All moving elements (road container, car elements, player wrapper) declare will-change: transform and use translate3d transforms. This promotes the elements to their own compositor layers, keeping animations off the main thread.
  • DOM recycling — Lanes more than six positions behind the player are removed from the DOM automatically. Cars and barriers within those lanes are also removed from the activeCars and activeBarriers arrays. This prevents unbounded DOM growth during long play sessions.
  • Delta-timed animation — The sprite frame timer uses a timestamp delta so the character animation runs at a consistent 24 fps regardless of the actual display refresh rate.
  • requestAnimationFrame loop — The game loop is driven by requestAnimationFrame, which pauses automatically when the browser tab is hidden, conserving CPU and battery.
  • Polyphonic audio via cloneNode — Sound effects do not allocate new AudioContext nodes or decode audio data on each play. Cloning a DOM Audio element is a lightweight operation.
  • Image pre-loading — All sprite sheet Image objects are created and their src assigned at module load time, ensuring assets are cached before the first game round begins.
  • CSS transition reuse — Player and road movement are handled by CSS transitions rather than JavaScript-driven requestAnimationFrame tweens. This reduces script execution per frame.

Recommendations for Production

  • Serve all assets (images, audio, JavaScript) with HTTP caching headers (Cache-Control: max-age=31536000 for static assets).
  • Enable GZIP or Brotli compression on your web server for the JS and CSS files.
  • If the game is embedded inside a larger page, ensure the embedding container does not apply overflow: hidden or transform on an ancestor element, as this can break fixed positioning used by the sidebar and toast.
  • For mobile deployment, verify that the viewport meta tag remains intact: width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no.

Common Issues & Troubleshooting

The game shows a blank screen or the road does not appear

This is almost always caused by opening index.html directly from the file system using the file:// protocol. The browser blocks ES6 module imports in this context. Use a local web server as described in the Installation section.

No sound is playing

  • Verify that the audio files exist at assets/audio/ with the correct file names.
  • Check that the browser has not blocked autoplay. Interact with the page (press Play) before expecting audio.
  • Confirm the Music Volume and SFX Volume sliders in the sidebar are not set to zero.

Vehicle images are not displaying (cars appear invisible)

  • Confirm that assets/images/1.png through assets/images/9.png are present and correctly named.
  • Verify the image paths in js/sprites.js (carImageAssets array) match the actual file locations relative to the HTML file.

The character sprite is a coloured circle instead of the chicken graphic

This is the fallback rendering drawn when the sprite sheet images have not finished loading or cannot be found. Confirm that assets/images/idle.png, assets/images/jump.png, and assets/images/crash.png are present and correctly named.

The game throws a JavaScript error in the browser console about "import"

The browser does not support ES6 modules, or the file is being served over file://. Switch to the single-file version by replacing the script tag in index.html to use js/h.js without type="module".

The sidebar panel or win toast appears behind other elements

An ancestor element in your hosting page may have a CSS transform or overflow: hidden property that creates a new stacking context, breaking position: fixed. Remove or adjust that property on the ancestor element.

The player character jumps off-screen or the road scrolls incorrectly

This may occur if the LANE_WIDTH constant in js/app.js has been changed without updating the corresponding width and min-width values in the .lane and .footpath CSS rules in styles.css. Ensure all three values are identical.

Security & Best Practices

Client-Side Seed Generation

In the current implementation, both the server seed and client seed are generated in the browser. The server seed is a prefixed random string (SRV_ + Math.random()) and the client seed is a prefixed timestamp (CLI_ + Date.now()). These are combined with the round nonce to seed the PRNG for each game round.

For a demo or entertainment context this is acceptable. For a real-money or competitive deployment, the server seed should be generated and kept secret on a trusted back-end server and only revealed to the player after the round ends, to achieve full provably-fair compliance. Implementing this requires back-end development beyond this package.

Input Validation

Bet input is sanitised in handleCustomBetInput(): non-numeric values default to MIN_BET, and values outside the MIN_BET–MAX_BET range are clamped. The setFixedBet() function also clamps values before assigning them.

State Integrity

Multiple guard conditions prevent actions during invalid states. The performJump() and cashoutGame() functions return immediately if isGameSessionActive is false, if isGameOver is true, if a crash animation is in progress, or if the player is mid-jump. This prevents duplicate actions from rapid button presses.

Deployment Recommendations

  • Serve the game over HTTPS to prevent asset interception and to satisfy browser security requirements for audio.
  • Do not expose the PRNG seed logic as an API endpoint, as it could allow players to predict outcomes before placing bets.
  • If embedding in a real-money platform, move all outcome determination to a trusted server and treat the client as display-only.
